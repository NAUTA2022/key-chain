# Idiomas (i18n)

La web está en **español (fuente)**, **inglés** y **árabe** (derecha a izquierda). Todos los textos de la interfaz viven en diccionarios JSON; el botón de idioma elige cuál se usa.

## Dónde está cada cosa

| Archivo | Para qué |
|---|---|
| `app/i18n/config.ts` | Idiomas (`LANGS`), nombre, código corto, dirección (`ltr`/`rtl`) y locale de cada uno. |
| `app/i18n/locales/<idioma>/<namespace>.json` | Los diccionarios. Un JSON por idioma y por zona de la web. |
| `app/i18n/messages.ts` | **Único punto de carga** de los diccionarios (`loadMessages`). Aquí se conecta un sistema de traducción. |
| `app/i18n/I18nProvider.tsx` | Idioma activo; aplica `lang` y `dir` al `<html>`; guarda la elección (`localStorage.bk_lang`, o `?lang=en` en la URL). |
| `app/i18n/useT.ts` | Hook `useT('namespace')` → `{ t, raw, lang, dir, locale }`. |
| `app/i18n/LanguageSwitcher.tsx` | Botón de idioma (landing y barra superior de la plataforma). |
| `scripts/i18n-check.mjs` | `npm run i18n:check`: todos los idiomas tienen las mismas claves que el español y toda clave usada en el código existe. |

## Namespaces

| Namespace | Zona |
|---|---|
| `common` | Compartido: barra lateral, barra superior, componentes UI, categorías, etapas y países. |
| `landing` | Página principal. |
| `market` | Mercado primario, detalle del proyecto, checkout, mercado secundario. |
| `portfolio` | Mi dashboard, Mis pertenencias, wallet. |
| `profile` | Perfil, cuenta y seguridad, perfiles sociales y de empresa, KYC. |
| `help` | Ingreso, Academia, Centro de ayuda, soporte, guías y onboarding. |
| `data` | Contenido de demostración por id: proyectos (nombre, ubicación, descripción, vida útil), tarjetas de la academia, logros y movimientos de la wallet. Se aplica con `useDataText()` (`app/i18n/data.ts`); el catálogo demo ya sale traducido de `useCatalog()`. Los datos en vivo de la API se muestran como llegan. |

## Reglas para escribir código

```tsx
import { useT } from '~/i18n/useT';

function Hero() {
  const { t, raw } = useT('landing');
  const stats = raw<{ value: string; label: string }[]>('hero.stats'); // listas: arrays en el JSON
  return <h1>{t('hero.title')}</h1>;
}
```

- **Nunca texto fijo en la interfaz**: todo lo que lee una persona (incluidos `aria-label`, `title`, `alt` y `placeholder`) sale de `t()`.
- **Claves en inglés, por zona y con sentido**: `hero.title`, `filters.country`, `buy.subtotal`. Las mismas claves en los tres idiomas.
- **Variables con `{{nombre}}`**: `"tokensLeft": "Quedan {{count}} tokens"` → `t('tokensLeft', { count })`.
- **Listas en el JSON** (arrays u objetos) y se leen con `raw()`. Las constantes de módulo con textos se mueven al componente o guardan solo claves.
- **Valores de datos** (categoría, etapa, país) se guardan en español en los datos y se traducen al mostrarlos: `t('categories.' + asset.cat)` con `useT('common')`.
- **No se traduce**: nombres de marca (Brikme, BRIKME, VARA, USDC, Polygon, thirdweb), el eslogan "Real World Tokenization", nombres propios de proyectos, empresas y personas, ni contenido que viene de datos o de la API (descripciones de proyectos, artículos de la academia, textos legales).
- Flechas de dirección (← →) dentro de un `<span className="rtl-flip">` para que se inviertan en árabe; posiciones con propiedades lógicas (`insetInlineStart`, `marginInlineStart`, `textAlign: 'start'`) en vez de `left`/`right`.
- Después de cambiar textos: `npm run i18n:check`.

## Traducciones

- **Inglés**: natural y profesional para inversionistas (no literal).
- **Árabe**: árabe estándar moderno (فصحى), tono financiero formal; números y cifras en dígitos occidentales (como en la UI); nombres de marca en caracteres latinos.
- El árabe se muestra de derecha a izquierda automáticamente (`dir="rtl"` en `<html>`), con la tipografía IBM Plex Sans Arabic y sin espaciado entre letras.

## Conectar un sistema de traducción

1. Los JSON usan el formato de i18next (claves anidadas, `{{variables}}`), que importan y exportan Crowdin, Lokalise, Locize, Phrase y Tolgee. Se pueden sincronizar tal cual con el repositorio.
2. Para servir las traducciones desde el sistema (sin publicar el sitio), reemplazar el cuerpo de `loadMessages(lang)` en `app/i18n/messages.ts` por un `fetch` al proveedor que devuelva `{ [namespace]: json }`. El español sigue incluido en el bundle como respaldo.
3. Un idioma nuevo: agregarlo en `LANGS` y `LANG_META` (`config.ts`), crear `locales/<idioma>/` con los mismos archivos y correr `npm run i18n:check`.
